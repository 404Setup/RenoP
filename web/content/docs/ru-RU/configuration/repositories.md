# Репозитории и зеркала

Определения репозиториев хранятся в базе данных и редактируются в управлении репозиториями. При первом
обновлении RenoP импортирует `repositories.yaml` (или `RENOP_REPOSITORIES`) только при отсутствии настроек в базе,
затем архивирует исходный файл как `repositories.yaml.migrated.<id>`. Ошибка входных данных останавливает запуск
без замены исходного файла. Настройки базы всегда имеют приоритет, включая пустой набор репозиториев. Новая
установка оставляет список репозиториев пустым и не создаёт YAML-файл. Сохраняйте резервную копию базы и защищайте архив,
который может содержать ключи S3 и зеркал. Имя — неизменяемый slug в нижнем регистре и первый сегмент URL.

Новая установка начинает работу с пустым списком репозиториев. Создавайте их явно на странице администрирования. Существующие снимки базы данных и однократный импорт старой конфигурации сохраняют настроенные репозитории.

## Пример миграции старой конфигурации

```yaml
repositories:
  releases:
    name: releases
    format: maven
    visibility: PUBLIC
    allow_redeployment: false
    require_gpg_signature: true
    publication_review: every_version
    download_statistics: true
    mirrors: []
  crates:
    name: crates
    format: cargo
    visibility: PUBLIC
    mirrors: []
  containers:
    name: containers
    format: docker
    visibility: PRIVATE
    allow_redeployment: false
    mirrors: []
```

## Поля репозитория

| Поле                    | По умолчанию      | Описание                                                                         |
|:------------------------|:------------------|:---------------------------------------------------------------------------------|
| `name`                  | Обязательно       | Неизменяемый slug и префикс URL                                                  |
| `format`                | `maven`           | `maven`, `maven-classic`, `files`, `npm`, `cargo`, `docker`, `conan`, `conda`, `conda-native`, `apk`, `apt`, `rpm`, `yum` |
| `visibility`            | `PUBLIC`          | `PUBLIC`, `HIDDEN` или `PRIVATE`                                                 |
| `allow_redeployment`    | `false`           | Повтор Maven или замена files/Docker, если поддерживается                        |
| `require_gpg_signature` | `false`           | Проверка отделённой OpenPGP подписи для Maven                                    |
| `publication_review`    | `off`             | Режим проверки Maven/npm/Cargo/Docker: `off`, `new_packages` или `every_version` |
| `download_statistics`   | Зависит от движка | Включено для Maven/npm/Cargo/Docker; для `files` включается явно                 |
| `mirrors`               | `[]`              | Упорядоченные upstream definitions                                               |
| `s3`                    | отсутствует       | Отдельное S3-хранилище репозитория                                               |

Для npm и Docker режим `new_packages` проверяет явный запрос на создание до резервирования имени, а `every_version`
также проверяет каждую следующую версию или manifest. У Maven и Cargo нет этапа создания пустого пакета, поэтому их
режим `new_packages` проверяет первую публикацию. Импорт из зеркала всегда обходит проверку.

`maven-classic` меняет только компоновку интерфейса и сохраняет правила публикации Maven. `files` неструктурирован,
не создаёт контрольные суммы и POM и не проверяет подписи. Миграция Maven ↔ `files` не перемещает объекты; возврат в
Maven перестраивает каталог и восстанавливает сохранённую политику. Настройка статистики скачиваний также сохраняется.

Загрузка и получение из зеркал в `files` сохраняют соседние файлы, даже если путь содержит `SNAPSHOT` или имя
заканчивается на `.md5`, `.asc` либо `-javadoc.jar`. Очистка версий и распаковка Javadoc применяются только к Maven.

Проверка публикаций поддерживает Maven, npm, Cargo, Docker и управляемых нативных ресурсов. Для Maven `allow_redeployment` принудительно становится
`false`; npm
сохраняет транзакцию неизменяемой версии и dist-tag. Локальные файлы скрыты до одобрения модератором репозитория или
системным администратором, а зеркала не проверяются. Репозиторий с ожидающей задачей нельзя изменить, удалить или
перевести на другой движок.

Репозиторий `npm` требует резервирования до публикации, хранит неизменяемые SemVer и dist-tag, поддерживает scoped
private packages, команды L0-L4 и зеркала по точному имени или правилу `@scope/*`.

### Видимость

- **PUBLIC**: разрешены анонимное чтение и обнаружение.
- **HIDDEN**: не отображается в каталогах для анонимных пользователей и пользователей без прав, а также в профилях.
  Администраторы и пользователи с явным правом просмотра видят репозиторий; точный путь к файлу остаётся доступным.
- **PRIVATE**: чтение, список и запись требуют явного права. Закрытый Docker image также проверяет L0-L4.

## Upstream-зеркала

Отсутствующий object можно потоково получить с включённого зеркала и сохранить без полного buffer. Cargo и Docker
запрещают локальное создание, если подходящее имя существует upstream.

```yaml
mirrors:
  - name: "central"
    url: "https://repo1.maven.org/maven2"
    persist: true
    cache_ttl_secs: 86400
    negative_cache: true
    timeout_secs: 30
    proxy: ""
    allow_artifacts: []
    deny_artifacts: []
```

| Поле              | По умолчанию | Описание                                         |
|:------------------|:-------------|:-------------------------------------------------|
| `name`            | Обязательно  | Уникальное имя в репозитории                     |
| `url`             | Обязательно  | Базовый upstream URL                             |
| `persist`         | `true`       | Сохранять успешные ответы                        |
| `cache_ttl_secs`  | `86400`      | Срок положительного cache                        |
| `negative_cache`  | `true`       | Cache поддерживаемых upstream miss               |
| `timeout_secs`    | `30`         | Timeout одного запроса                           |
| `proxy`           | `""`         | Глобальный route, `direct` или именованный proxy |
| `allow_artifacts` | `[]`         | Правила разрешения с учётом формата              |
| `deny_artifacts`  | `[]`         | Приоритетные правила запрета                     |

Credentials задаются структурированными полями authorization и не встраиваются в `url`.

## S3-совместимое хранилище

Каждый репозиторий использует Disk или собственный S3. Repository gate сериализует смену storage/engine с uploads,
удалениями, GPG commit и mirror write.

```yaml
s3:
  enabled: true
  endpoint: "https://s3.us-east-1.amazonaws.com"
  bucket: "my-renop-bucket"
  key_prefix: "releases/"
  region: "us-east-1"
  access_key_id: "YOUR_ACCESS_KEY"
  secret_access_key: "YOUR_SECRET_KEY"
  force_path_style: false
  redirect_downloads: false
```

MinIO обычно требует `force_path_style`. При `redirect_downloads` RenoP авторизует запрос и отдаёт краткосрочный
подписанный redirect; иначе объект передаётся через RenoP.

`capacity_limit_bytes` задаёт лимит сохранённых байтов репозитория; `0` означает отсутствие лимита. Интерфейс использует MiB. Для Disk и S3 учитываются артефакты, контрольные суммы, объекты на проверке и кэш зеркал, без временных копий. Резервирование перед фиксацией объединяет параллельные загрузки под одним лимитом. Превышение возвращает `507` и `repository_capacity_exceeded`; корректный ответ зеркала можно передать без кэширования. Снижение лимита ниже текущего объёма не мешает чтению. После внешнего изменения хранилища перестройте индекс или перезапустите сервер для пересчёта. Пропуск необязательного поля старым клиентом сохраняет прежний лимит.

## Репозитории нативных пакетов

Conan поддерживает ревизии рецептов и бинарных пакетов через родной клиент. Conda и Conda native принимают `.conda` и `.tar.bz2` в каталогах платформ, например `noarch/`, и создают `repodata.json`. APK создаёт `APKINDEX.tar.gz` рядом с пакетами в каталогах архитектур, например `x86_64/`. apt принимает `.deb`, создаёт `Packages`, `Packages.gz` и `dists/<suite>/Release`, сопоставляя `pool/<component>/` соответствующему компоненту. rpm/yum создаёт `repodata/repomd.xml` и связанные метаданные.

Перед загрузкой зарегистрируйте нативный ресурс в браузере репозитория. Идентификатор берётся из метаданных пакета или рецепта Conan; префикс глобальной команды не требуется. L0 разрешает чтение, L1 — публикацию, L2 — замену и удаление версий, L3 — настройки и участников, L4 — владение. Должен остаться хотя бы один владелец L4. Право записи в репозиторий само по себе не даёт доступа к чужому ресурсу. Нативные зеркала доступны только для чтения.

`new_packages` проверяет первую публикацию после регистрации, `every_version` — каждую версию или ревизию Conan. Неполные подписи и ожидающие проверки файлы скрыты из загрузок и индексов, в том числе после перезапуска. APK требует открытый ключ RSA PEM и нативную подпись управляющей части и содержимого. RPM требует доверенную подпись OpenPGP, защищающую содержимое напрямую или через подписанный хеш. Ключ задаётся в настройках ресурса. APT подписывает индексы репозитория, отдельная подпись для каждого `.deb` не требуется. Conda использует родные хеши без дополнительного `.asc`.

Новые загрузки не могут заменять генерируемые индексы. Старые метаданные сохраняются до удаления администратором. Автоматический индекс ограничен 10 000 пакетов; крупные наборы следует разделять на репозитории или нативные подкаталоги. Размер пакета ограничен 8 GiB, число неопубликованных файлов — 256 на ресурс и 16 384 на экземпляр. Старые незарегистрированные файлы остаются доступны для чтения; конфликтующую замену должен сначала разрешить администратор.

Созданные метаданные APK, apt и rpm подписываются отдельными постоянными ключами из закрытой базы настроек. Открытые ключи доступны соответственно по путям `renop.rsa.pub`, `renop.asc` и `repodata/repomd.xml.key`. apt также предоставляет `InRelease` и `Release.gpg`, а rpm — `repomd.xml.asc`. Импортируйте ключ перед использованием команд из браузера репозитория. Подписи самих rpm-пакетов остаются ответственностью издателей и требуют их собственных ключей.

Conan использует манифест официального расширения подписи и OpenPGP. Установите `scripts/conan/sign.py` в `<CONAN_HOME>/extensions/plugins/sign/sign.py`, зарегистрируйте открытый ключ, задайте его отпечаток для подписи в `RENOP_CONAN_GPG_KEY` и доверенное бинарное хранилище открытых ключей для `gpgv` в `RENOP_CONAN_GPG_KEYRING`. Файлы скрыты, пока не получены все файлы манифеста и подпись. Повторная отправка идентичных опубликованных файлов Conan идемпотентна.

```sh
conan cache sign "PACKAGE/*"
conan upload "PACKAGE/*" --remote "REPOSITORY" --confirm
```


## Общие данные файлов

Одинаковые файлы Disk совместно используют неизменяемые данные через жёсткие ссылки, сохраняя логические пути. Запись атомарно заменяет файл; удаление одного пути сохраняет остальные ссылки. Единственная фоновая задача сканирует существующие файлы порциями, пропускает занятые репозитории и делает паузы. Изменяемые индексы, временные файлы и Disk-кеши зеркал со сроком действия остаются отдельными файлами.

Данные S3 размером от 64 KiB сохраняются через логические ссылки на общий объект; меньшие объекты сохраняются напрямую. Хеши и ссылки записываются в закрытый файловый индекс. Известные записи позволяют избежать повторных проверок метаданных. Старые объекты без надёжного хеша не изменяются до обычной загрузки или полного скачивания через RenoP, при котором хеш вычисляется попутно. Фоновая дедупликация не скачивает их только для сравнения. Перестроение индекса может читать страницы LIST и однократно проверять отсутствующие метаданные ссылок. Регулярная очистка обрабатывает очередь индекса вместо постоянного сканирования всего бакета.

Полная резервная копия S3 включает объекты репозиториев, закрытое пространство `.renop-content-v1` и закрытый индекс. Независимым установкам RenoP нужны разные префиксы ключей. Данные без ссылок удаляются после льготного периода. Ёмкость репозиториев и статистика скачиваний по-прежнему учитывают логические размеры файлов независимо от физического совместного хранения.
