# API хранилища и загрузки

Прямые маршруты предназначены для Maven, `files` и управляемых нативных репозиториев. npm, Cargo и Docker используют
нативные протоколы. Каждое изменение
проверяет scope API Token, права репозитория, формат и политику домена Maven.

## Прямые операции с репозиторием

Канонический путь — `/{repo}/{path...}`. Чтение поддерживает HTTP validators и диапазоны байтов. `HIDDEN` не попадает в
списки, но читается по точному пути; `PRIVATE` требует авторизацию.

### Скачивание

- **Запрос**: `GET /{repo}/{path}` или `HEAD /{repo}/{path}`
- Отсутствующий локальный файл может быть получен с включённого зеркала и кеширован по настроенной политике.

### Загрузка

- **Запрос**: `PUT /{repo}/{path}`
- **Аутентификация**: пароль или API Token с `repository:publish` и текущие права записи/домена.
- Maven принимает только корректные координаты и метаданные проверенного домена. `files` принимает безопасные
  произвольные пути и разрешает замену.

### Удаление

- **Запрос**: `DELETE /{repo}/{path}`
- **Аутентификация**: API Token с `repository:delete` или другой разрешённый способ и текущее право удаления.

## Блочные возобновляемые загрузки

Метаданные передаются в protobuf, части — сырые бинарные данные. Сервер контролирует конечный путь, ограничивает размер
и число сессий и удаляет заброшенные временные файлы.

### Инициализация

- **Путь**: `POST /api/upload/chunked/`
- **Content-Type**: `application/x-protobuf` / `application/json` с `ChunkedUploadInitRequest`.
- `purpose` — `storage` или `updater`. Для storage поле `path` начинается с имени репозитория.

```json
{
  "purpose": "storage",
  "filename": "app-1.0.0.jar",
  "size": 524288000,
  "path": "releases/com/example/app/1.0.0/app-1.0.0.jar",
  "generate_checksums": true,
  "chunk_size": 4194304,
  "gpg_signature_expected": false
}
```

### Загрузка части

- **Путь**: `PUT /api/upload/chunked/{upload_id}/{index}`
- **Content-Type**: `application/octet-stream`.
- Части можно отправлять параллельно. Повтор принятого index идемпотентен; неверная длина отклоняется.

### Завершение или отмена

- **Завершить**: `POST /api/upload/chunked/{upload_id}/complete`
- **Отменить**: `DELETE /api/upload/chunked/{upload_id}`
- Завершение имеет одного победителя, повторно проверяет части и права и фиксирует данные через gate репозитория.

```json
{
  "status": "created",
  "message": "",
  "path": "releases/com/example/app/1.0.0/app-1.0.0.jar",
  "release_id": ""
}
```

При обязательном GPG возможен `202 Accepted` с `release_id` на время карантина. Для `purpose=updater` успех возвращает
`ready_to_restart`, а не путь репозитория.

## API управляемых нативных ресурсов

Эти JSON endpoints управляют публикацией APK, apt, Conan, Conda/Conda native и rpm/yum. Изменения требуют Cookie-сессию
браузера. Клиенты используют родные пути; scope Token пересекается с текущими правами на ресурс.

| Операция | Endpoint                                                                | Назначение                                                                                             |
|----------|-------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------|
| `GET`    | `/api/native/repositories/{repo}/resources`                             | Список ресурсов; `name` выбирает детали, `limit` равен 1–100, `offset` — до 10000.                     |
| `POST`   | `/api/native/repositories/{repo}/resources`                             | Регистрация через `{"name":"example"}`; требуется право публикации в репозиторий.                      |
| `PUT`    | `/api/native/repositories/{repo}/resources`                             | Обновление `name`, `description` и открытого `signing_key`; требуется L3.                              |
| `DELETE` | `/api/native/repositories/{repo}/resources`                             | Освобождение пустого ресурса по `name`; требуется L4 и отсутствие ожидающих проверок.                  |
| `PUT`    | `/api/native/repositories/{repo}/resources/members`                     | Изменение `name`, `username` и `level` (0–4, либо -1 для удаления); последний владелец L4 сохраняется. |
| `GET`    | `/api/native/repositories/{repo}/resources/key?name={name}`             | Загрузка открытого ключа издателя с проверкой видимости неопубликованного ресурса.                     |
| `GET`    | `/api/native/repositories/{repo}/resources/users?name={name}&q={query}` | Поиск до восьми видимых пользователей для редактора прав L3.                                           |

`new_packages` проверяет первую публикацию, `every_version` — каждую версию. `202` означает, что файлы скрыты до
получения подписей или решения; для проверки возвращается `X-RenoP-Review-ID`. Имена файлов должны соответствовать
метаданным; загружать генерируемые индексы нельзя. APK и RPM требуют действительной нативной подписи настроенным ключом.
Conan требует подписанный манифест из `scripts/conan/sign.py`. APT подписывает индексы; Conda не требует дополнительной
отдельной подписи. См. [настройку репозиториев](/docs/configuration/repositories).
