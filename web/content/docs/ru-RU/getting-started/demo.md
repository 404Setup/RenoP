# Демонстрационный режим

Первый запуск с `--demo` создаёт отдельный набор данных, далее доступный только для чтения. Форма входа заполняется
`admin` / `12345678`. Примеры включают аккаунты, сессии, команды, Maven/Cargo/npm/Docker, метаданные файлов, проверки,
тикеты, квоты, уведомления, статистику, журналы и историю почты.

```bash
./renop --demo
./renop --demo --demo-temp
```

С `--demo --demo-temp` можно сохранять системные настройки и определения репозиториев. Изменения сохраняются;
перезапустите только с `--demo`, чтобы снова показывать их без записи. Один `--demo-temp` не допускается. Другие
изменения и запись журналов запрещены в обоих режимах.

По умолчанию используются `renop-demo.db` и `renop-demo-settings.db`; пути задают `RENOP_DEMO_DATABASE` и
`RENOP_DEMO_SETTINGS_DB`. Обычные данные изолированы. Существующий набор сохраняется, даже с пустым списком
репозиториев. Создаются только базы, без файлов пакетов, индекса или журналов; загрузка артефактов и предпросмотр
документации недоступны. Реальные сессии находятся в ограниченной памяти процесса, а предустановленные сессии не дают
доступ.

`GET /api/demo` возвращает бинарный protobuf `DemoInfo`: `enabled`, `temporary` и публичные демонстрационные данные
входа. Обычный режим не возвращает пароли. Запрещённые изменения получают `403` и `demo_read_only`, недоступные файлы —
`demo_file_unavailable`. Фоновые задачи почты, зеркал, обслуживания и обновлений не запускаются.
